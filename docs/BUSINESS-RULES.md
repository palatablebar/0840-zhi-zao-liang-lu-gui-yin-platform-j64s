# 业务规则

## 使用者

工厂工艺工程师使用本工作台处理首检良率与返工归因。

## 主规则

首检良率不把返工良品算作一次通过，滚动良率按各工序首检良率相乘。

计算以整数最小单位或十进制定点数为准，避免二进制浮点在边界上漂移。无法完成前置校验的行进入隔离区；跨行规则在计算后标记阻断或人工复核。

## 判定

- `PASS`：业务结果在允许范围内。
- `REVIEW`：数据可计算，但需要人工确认或存在轻微偏离。
- `REJECT`：存在来源、守恒、方向或上限阻断，不能签发。

## 批次

同一来源重复执行得到同一批次数值。签发要求阻断项为零，并携带当前版本号；旧版本提交会被拒绝。证据只在签发后生成。

## 规则版本与重算

工艺规则带版本号（`v1` 为初始规则，目标 0.90 / 下限 0.70；`v2` 为更新后的 0.95 目标）与明确的适用范围（`rule_scope` / `scope`）。规则更新后，批次可按新规则整体重算归因，新阈值会修正旧结论（例如 WO1 滚动良率 0.9025 在 v1 为 `PASS`、在 v2 为 `REVIEW`）。

- 重算一律整批重新执行采信、整理、计算与判定，每个结果行带同一 `rule_version` / `version`，不会把新规则行与旧规则行混在同一版本里。
- 修订请求按 `request_key` 幂等；未显式给键时，由批次、规则版本、范围、来源摘要与补齐数据摘要推导。重复执行同一修订请求返回同一条记录与同一个版本，绝不新增版本。
- 资料不齐导致重算中断时，修订为 `INCOMPLETE` 并列出 `incomplete_reasons` / `missing`；补齐数据后用同一请求（或 `/resume`）续跑，记录 id 与已分配版本号不变。
- 每次签发都固化一份不可变批次版本与签发记录（`batch_versions` / `issuances`）。新版本只新增快照，不改写旧快照；`GET /evidence?revision=N` 的摘要始终稳定。
- 签发候选版本前会复核来源摘要是否仍是当前来源、候选的来源/规则版本与请求声明是否一致；来源已变更或来源与规则版本不符时返回 `409`，不能签发。

## 生产日报

生产日报（`production-daily-report/v1`）在生成时固定引用某个已签发版本（`run_id` + `version/revision` + `rule_version` + 证据摘要），并固化当时的结论行。之后按新规则重算、发布新版本都不会改变已出日报；历史日报始终能凭保留的签发记录与证据回溯来源摘要和规则版本。

工作台批次视图明确给出：`publishable_version`（当前可发布的候选版本）、`rule_scope`（规则范围）与 `incomplete_reasons`（未完成原因），并列出全部批次版本及其 `READY/ISSUED` 状态。
